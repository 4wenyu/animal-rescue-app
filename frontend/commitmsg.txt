feat(epic2): wire complete viral-share loop — share button + landing page + landing reward

Three coordinated changes ship as a single feature:

1) lib/services/tokenService.ts
   - Replaced the awardShareReward STUB with a real implementation.
   - Spending shape: +5 EARN/SHARE_10_GROUPS_EARN per landing.
   - Rate limit: in-memory Map<(shareId, ip), timestamp>; the second hit
     for the same share+ip within 24h returns { skipped: true } with no
     ledger write.
   - Idempotency key is `share-<shareId>:landing:<ip>` so retries across
     processes can't double-mint.
   - sourceViralShareId is set on the ledger row so /api/tokens/wallet
     could audit who triggered the reward.

2) /p/[shareId] — new public landing route
   - Server Component, reads params.shareId, looks up the
     ViralShareVerification row.
   - Captures visitor IP from x-forwarded-for / x-real-ip headers.
   - Calls awardShareReward(userId=share.userId, shareId, ip).
   - Bumps observedAt on first visit (placeholder for the future
     verifier-cron).
   - Renders the published animal profile by looking up relatedAnimalId
     inside evidenceSnapshot and pulling the row from data/dogs.json.
   - Two UI states: first-visit amber reward toast, repeat-visit slate
     dedup notice.

3) /api/shares update
   - Accepts optional relatedAnimalId (the animal being shared).
   - Persists it inside evidenceSnapshot (since there's no direct column
     in ViralShareVerification for it).
   - Returns trackingUrl of the form `/p/<shareId>` (changed from
     earlier /r/<animalId>?utm=… design — shareId IS the routing key).
   - Adds a dead-letter shareId echo for debugging dedup skips.

4) ShareToHelpButton client component
   - Posts to /api/shares with the row's animal.id.
   - On 201, copies returned trackingUrl to clipboard with the standard
     navigator.clipboard + execCommand fallback.
   - Inline fixed-position toast shows the URL for 4s, then auto-clears.
   - `onClick={(e) => e.stopPropagation()}` so the row's "go to profile"
     handler doesn't fire when the share button is clicked.

5) AnimalTable.tsx — wired <ShareToHelpButton> into the existing
   ActionButtons column next to Adopt/Transfer. Visible even on HAYDEN-
   locked rows because "share to recruit your socials to save this
   animal" is exactly what urgent cases need.

Live test workflow:
  1. Restart `npm run dev` to clear stale module cache.
  2. Sign in admin@…, click 🔗 Share to Help on a row.
  3. Toast appears with the `/p/<uuid>` URL; clipboard also has it.
  4. Paste into an incognito window (different IP — different dev server
     startup uses 127.0.0.1 typically).
  5. Visitor lands → "+5 tokens minted to the sharer" toast appears on
     page. The dashboard wallet bumps by 5. A second visit from the
     same IP within 24h shows the dedup slate notice instead.
